01

Product & roles

Tempo plans and tracks structured endurance training (run / bike / swim / row). One account model carries a role; the data model is shared, the home & navigation differ.

Athlete

Follows a plan, executes & logs sessions, can edit their own copy. Works solo or with a coach.

Coach

Manages a roster, builds sessions & plans, assigns them, monitors compliance, adjusts.

Self-coached

An athlete with builder tools unlocked — no coach attached. Toggle in profile.

Object
Meaning
Plan
A dated arc of training (e.g. 12-week build to a race), made of weeks of sessions.
Session
One workout on one day. Has a sport, target metric, and an ordered list of blocks.
Block
A step within a session — duration + intensity zone (+ optional reps). Renders as one segment of the block bar.
Template
A saved, reusable session with no date — dropped into a plan and scheduled.
Activity
A completed session — actuals logged against the plan (compliance %).
02

Principles

1 · Colour means intensity

Saturated hues are reserved for zones; the shell stays neutral so a glance reads effort.

2 · Calm by default

Warm paper, generous space, hairline borders before shadows.

3 · Numbers are tabular

Durations, watts, TSS and dates align and never jitter as values change.

4 · One accent, used rarely

Sage marks the active place and brand moments only.

5 · Built for the thumb

Tap targets ≥44px; the live session shows one step at a time.

6 · Athlete chooses depth

Optional overview cards are opt-in from Settings, not forced on everyone.

05

Components

Full visual reference lives in Design System. Behaviour notes below.

Session block bar · signature

Horizontal flex row; each block = a segment with flex-grow = duration and background = zone solid. 2px gaps, 8–9px radius on the container. Drives the home card, session detail, builder & templates. Mobile compresses height to ~22px.

Buttons

Primary = ink fill / white text. Brand = sage fill. Secondary = surface + border. Ghost = text only. Radius 10 (8 sm / 12 lg). Hover darkens fill ~8% or tints ghost. Disabled = sunken bg, ink-3 text.

Badges & status

Pill, tint bg + matching text colour. Planned (sage), Completed (green, dot), Adjusted by coach (amber), Today (ink), Rest (dashed), Missed (blue). Compliance % reuses these.

Stepper

− / value / + in a bordered 40px-tall group. Used for intervals, durations, recovery. Clamp to sane min/max. Value is tabular.

Calendar cell & session chip

Day cell holds a date header + stacked session chips (tint bg, 3px zone left-accent, title + duration·sport). Multiple sessions stack vertically. Today = ink border; weekend = faint paper.

Nav item · segmented · toggle

Active nav = sage-tint pill + 3px sage left bar. Segmented (Week/Month) = sunken track, active pill on surface w/ subtle shadow. Toggle = 42×24 pill, sage when on.

06

Screens

Athlete · desktop → Tempo App
Home

Greeting → today's sessions (1..n cards, each with block bar & target) → next-days strip. Right rail = optional cards (coach note, last activity, weekly load, fitness trend) governed by Settings → Overview. Session card click → Session.

Calendar

Segmented Week ⇄ Month. Week = 7 columns, sessions stacked, footer week-total + load-by-zone bar. Month = grid with per-day zone bars + overflow. Date nav, sport filter, + Add. Same data both views.

Session + adjustment

Header (sport, date, duration, TSS, Planned/Adjusted) → block bar → Adjust panel: steppers for intervals / work / recovery + intensity cycle. Edits recompute bar, duration, TSS live and flip status to Adjusted with an "originally…" note. Athlete/Coach context changes the save action. Save as template.

Activity & Settings → Overview

Activity = completed sessions w/ zone distribution + compliance. Settings → Overview = toggles that decide which optional Home cards show (today's sessions always show).

Mobile → Tempo Mobile
Home · Calendar · Session · Live execution

Bottom tab bar (Home / Calendar / + / Activity / You). Live execution is the centrepiece: dark full-screen mode, progress dots (done / current / upcoming), big timer, zone chip, target, next-up preview, and a large Next / Lap control that advances the step. Tap targets ≥44px.

Coach → Tempo Coach
Athletes (roster) & Athlete detail

Roster table: athlete, week compliance bar, status flag, next session → row click opens detail (stats, this-week calendar, planned-vs-done, Build session).

Plan builder & Templates

Builder = the same interactive block bar + set steppers, beside an Assign panel (multi-select athletes, pick date; button counts recipients). Assigned sessions land on athlete calendars flagged "by coach". Templates = reusable session cards → load into builder.

07

Key interactions

Adjust a session

Steppers mutate reps / work / recovery / zone → derive blocks → block bar + duration + TSS recompute. Diff vs plan flips status to Adjusted. "Reset to plan" reverts. Coach edits push to the athlete; athlete edits stay on their copy.

Assign (coach)

Build/select a session → tick athletes → pick date/time → Assign. Creates a scheduled Session on each athlete's calendar with source: coach.

Live execution

currentStep index over the flattened block list. Next/Lap advances; progress dots + timer + target + zone reflect the active block. (Wire a real countdown + auto-advance to block duration.)

Overview density

Per-user prefs decide which optional Home cards render. Persist on the user; today's sessions are never hidden.

08

Data model & build notes

User        { id, name, role: 'athlete'|'coach', selfCoached: bool, coachId?, prefs: { overviewCards: string[] } }
Plan        { id, athleteId, name, startDate, endDate, goalRace? }
Session     { id, athleteId, date, time, sport, status: 'planned'|'completed'|'missed',
              source: 'self'|'coach', adjusted: bool, plannedFrom?, blocks: Block[] }
Block       { id, kind: 'warmup'|'work'|'recovery'|'cooldown', zone: 1..5,
              durationSec, reps?, target?: { type:'power'|'pace'|'hr', low, high } }
Template    { id, ownerId, name, sport, blocks: Block[] }       // Session without a date
Activity    { id, sessionId, athleteId, completedAt, durationSec, tss, compliancePct,
              zoneDistribution: number[5] }
Assignment  { sessionId, athleteIds[], date, assignedBy }       // coach → athletes
Derived, never stored

Total duration, TSS, and the block-bar geometry are computed from blocks. Compliance = actual vs planned TSS/duration.

Responsive

Desktop sidebar collapses to the bottom tab bar <768px. Calendar week → agenda list on mobile. Right rail stacks under main.

Accessibility

Zone colour is always paired with a Z-label or name — never colour alone. Tap targets ≥44px. Body contrast ≥ AA on paper. Tabular figures for all metrics.

States to add

Empty (no sessions / no athletes), loading skeletons, error/offline, and a real countdown + auto-advance in live execution.

How to hand this to an implementer

Map the hex values above to your token names first (Tailwind theme / CSS vars), then build screen-by-screen from the matching DC file. Each screen file uses these exact values, so visual parity is a token lookup away. The block bar, stepper and badge are the highest-reuse components — build them once.
