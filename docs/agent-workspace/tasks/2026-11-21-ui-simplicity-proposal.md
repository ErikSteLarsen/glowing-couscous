# Tempo UI simplicity proposal

Read-only audit for item-by-item approval. I inspected the seeded athlete app as Mara at 1440 × 1000 and 390 × 844 in Chromium on the existing local server. I opened pages, menus and unsaved editors. Electron handoff, physical Bluetooth, connected Strava, populated Templates and populated Events were source-reviewed only. The phone captures test a viewport in Chromium. Screenshots are in the audit scratchpad. Only this Markdown was added to the worktree.

Keep Calendar's pick → when → confirm flow, Tempo's shared interaction patterns, and the one deterministic Back control on detail screens. S is local, M spans a feature or shared component, and L spans multiple routes or write paths.

## 1. P1 · One Start workout chooser · L

**Today.** Home starts Live directly. Bike session detail exposes Start live, Ride with trainer and Open in Tempo Ride app. Library detail has two start buttons and Ride home cards have one. [Session 1440](/tmp/tempo-ui-audit-df353/session-1440.png) · [Session 390](/tmp/tempo-ui-audit-df353/session-390.png) · [Library detail 390](/tmp/tempo-ui-audit-df353/library-detail-390.png)

**Change.** Use one visible **Start workout** per runnable item at each existing direct start. The chooser names the workout and shows actionable buttons with one sentence each. Selecting one opens the runner. Keep the runner's own controls for pairing, starting the timer or recording, and resuming. Calendar cards, standard Library cards and Home agenda titles continue to open detail. Personal Workouts and Templates keep their scheduling paths.

**Why.** The surface answers “I want to do this workout.” The chooser answers where and what Tempo will capture.

Desktop with all three destinations:

```text
+-------------------------------------------------------------+
| Start workout                                         [ X ] |
| Gentle Spin · 30 min                                         |
|                                                             |
| [ Open in Tempo Ride                                      ] |
|   Use Bluetooth devices in the desktop app.                  |
| [ Ride in this browser                                    ] |
|   Use Bluetooth devices or ride to the targets.               |
| [ Follow along                                            ] |
|   Use a step timer and advance through the workout yourself. |
|                                                   [ Cancel ] |
+-------------------------------------------------------------+
```

Phone without Web Bluetooth:


Use the shared modal interaction and focus styling. Stack full-width buttons in a bottom-aligned phone dialog with safe-area clearance, contained scrolling, Close/Escape, and focus return. If opened from a menu, restore focus to the trigger. Keep route-level Back navigation through allowlisted origins and sign-in.

| Session and environment | Choices |
|---|---|
| Open bike, Windows/macOS/Linux web browser with Web Bluetooth | **Open in Tempo Ride**, **Ride in this browser**, **Follow along**. |
| Same OS without Web Bluetooth | **Open in Tempo Ride**, **Follow along**, **Ride with targets only**. Targets-only opens the browser ride runner. |
| Phone/tablet or other OS with Web Bluetooth | **Ride in this browser**, **Follow along**. Gate on actual runtime capability. |
| Phone/tablet or other OS without Web Bluetooth | **Follow along**, **Ride with targets only**. |
| Already inside Tempo Ride, open bike | **Ride in Tempo Ride** opens the runner in this window, then **Follow along**. If Bluetooth is unavailable, describe the first option as targets-only. |
| Open running, swimming, strength or stretching with executable steps | **Follow along** as the single start option. Keep post-workout logging in session detail and Activity. |
| Rest or no executable steps | Show details and eligible status/completion actions. Today the routes allow some empty plans to reach a runner. An intentional free-ride entry would be a separate decision. |
| Completed or skipped | **Review outcome** or **View activity data** for completed. **Plan again** for eligible skipped sessions. **Again** on a catalog-backed ride leads to the catalog, where starting uses a separate copy. |

**Fallback.** The desktop OS indicates compatibility. Website signals such as blur and timeout cannot confirm installation. Keep the existing OS downloads and retry inside the chooser and say “Tempo Ride may not have opened.” Keep browser choices available. For catalog starts, explain “Adds this workout to today” before selection. Create or reuse the same local-day session after selection. Keep that ID through retry, browser/protocol fallback and the proposed new catalog-to-Live route. If a protocol prompt is blocked after the preparation request, offer a second explicit handoff click. Before selection, Cancel leaves the calendar as it was. After creation, show the scheduled copy and **View session** if launch needs recovery.

**Default (decided 2026-11-21: ask each time; no saved preference in this pass).** Ask each time at first. If repeat use warrants a preference, place **Preferred bike option** under **Settings → Workout start** on this device, with **Ask each time** as the default. Highlight or order a preferred available option while keeping the choice visible.

**Risk and dependencies.** Share eligibility with the runners and preserve authorization, catalog idempotency, distinct checkpoints, and browser/desktop Back origins. Verify keyboard behavior at both sizes, unsupported Bluetooth, auth callbacks, rejected permissions, and app handoff/fallback on each supported desktop OS. ### Actual modes

| Mode | Current behavior |
|---|---|
| Live guidance | Generic stepper for unskipped blocks with a user-operated timer, manual advance, browser-local paused recovery, no sensor telemetry, and explicit completion. Runs bike and non-bike plans with steps. |
| Indoor ride in the browser | Bike only. Automatically times intervals, can record Bluetooth sensor data and control a compatible ERG trainer. Targets-only is a variant of this runner that saves ride time without sensor data. Saving uses the Activity import path. |
| Indoor ride in Tempo Ride | The same bike runner inside Electron with a native Bluetooth picker and additional user/site-scoped checkpoint backups. The window.tempoDesktop bridge supplies identity, version and recording IPC. |
| Manual completion and logging | Post-workout. Session detail can complete from the plan and note, or correct eligible outcomes. Activity can log actual summaries for running, biking, swimming, strength and stretching, standalone or explicitly paired to an eligible same-day, same-sport self-planned session. File/Strava import reviews recorded data. Keep these outside the start chooser. |
