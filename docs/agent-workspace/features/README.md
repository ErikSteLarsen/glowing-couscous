# Feature Records

Feature records are the detailed, stable view of one capability. Keep one
record per capability instead of scattering implementation notes across task
files. Update the record when behavior, owner, entry point, verification, or
known gaps change.

Use `TEMPLATE.md` for a new feature. Every record must have:

- a stable ID matching `WORK-INDEX.md`;
- a current status and last-verified date;
- the live routes, services, data, and shared UI involved;
- verification evidence and known gaps;
- extension rules for the next agent;
- a short dated history table.
